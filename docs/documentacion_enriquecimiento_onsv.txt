1. Objetivo del notebook 02

El objetivo del notebook 02 es enriquecer la base limpia generada por el notebook 01 con fuentes oficiales externas y relacionales.

El notebook 02 no realiza feature engineering de modelado ni crea la variable objetivo. Es decir, no genera columnas como AÑO, MES, FRANJA_HORARIA, REGION_NATURAL, CATEGORIA_SEVERIDAD, MORTALIDAD_MULTIPLE o LESION_MULTIPLE. Esas variables corresponden al notebook 03.

2. Entrada del notebook 02

Archivo de entrada:

- data/procesada/siniestros_limpio.csv

Este archivo viene del notebook 01 y representa la limpieza estricta del archivo original. Contiene:

- 9,106 filas
- 27 columnas limpias originales
- CÓDIGO SINIESTRO como identificador del siniestro

El notebook 02 usa ese identificador como llave primaria para validar cruces, especialmente con las bases de PERSONAS y VEHÍCULOS de ONSV.

3. Validación inicial de columnas

El notebook 02 valida las columnas del dataset limpio mediante alias normalizados. Esto evita depender de nombres exactos con tildes, espacios o variaciones menores.

Ejemplo:

- CÓDIGO SINIESTRO se estandariza internamente como CODIGO_SINIESTRO.

Esta estandarización se usa solo para que los merges sean consistentes. No representa una etapa de feature engineering.

6. Prevención de fuga de información

Para evitar fuga de información, no se usan variables que revelen directamente el desenlace del siniestro, como:

- GRAVEDAD de la persona
- LUGAR ATENCIÓN LESIONADO
- LUGAR DE DEFUNCIÓN
- Conteos directos de fallecidos o lesionados desde la base de personas

El target y las columnas derivadas de modelado quedan para el notebook 03.

7. Validaciones realizadas

El notebook 02 valida:

- existencia de columnas requeridas del limpio mediante alias normalizados
- consistencia y unicidad de CODIGO_SINIESTRO
- filas antes y después de cada merge
- duplicados generados por merge
- cobertura por fuente
- porcentaje de nulos nuevos
- encoding de salidas en utf-8-sig

8. Salidas generadas

Archivos generados:

- data/procesada/trazabilidad_variables_externas.csv

Resultados finales:

- 9,106 filas
- 73 columnas finales
- 27 columnas provenientes del limpio del notebook 01
- 46 variables nuevas de enriquecimiento
- 0 duplicados en CODIGO_SINIESTRO

9. Relación con el notebook 03

El archivo data/procesada/siniestros_enriquecido.csv debe ser la entrada para el notebook 03.

En el notebook 03 corresponde crear:

- variables temporales y derivadas
- variable objetivo
- selección de features
- encoding
- imputación para modelado
- SMOTE
- partición train/test

De esta forma, el pipeline queda separado correctamente:

- NB01: limpieza estricta
- NB02: enriquecimiento externo/relacional
- NB03: preparación para modelado y feature engineering
