1. Objetivo del trabajo realizado

El objetivo del punto de enriquecimiento fue ampliar la base limpia de siniestros fatales de tránsito del Perú con información real y trazable. El proceso se integró dentro del notebook 02, para que el pipeline quede ordenado así:

- Notebook 01: limpieza y EDA inicial.
- Notebook 02: enriquecimiento externo y relacional.
- Notebook 03: preparación para modelado.

El notebook principal de este punto es:

- notebooks/02_enriquecimiento_externo.ipynb

3. Qué se agregó en el notebook 02

Se corrigió y amplió el notebook 02 para que realice todo el enriquecimiento en un solo flujo reproducible. Ya no depende de hacer el enriquecimiento principal mediante un script separado.

El notebook ahora incluye:

- Lectura segura del CSV limpio con prioridad en utf-8-sig.
- Corrección/verificación de encoding en outputs.
- Reconstrucción de variables derivadas si el limpio nuevo no las trae.
- Validación de CODIGO_SINIESTRO como llave única.
- Enriquecimiento con fuentes MTC e IDH.
- Enriquecimiento con personas y vehículos ONSV.
- Validación de merges.
- Reporte de porcentaje de nulos en variables nuevas.
- Exportación de la base final y trazabilidad en utf-8-sig.

4. Variables reconstruidas para mantener compatibilidad con el notebook 03

Como el csv limpio nuevo trae la información base, pero no todas las variables derivadas que necesita el modelado, el notebook 02 reconstruye cuando sea necesario:

- AÑO
- MES
- DIA_SEMANA
- ES_FIN_SEMANA
- HORA_NUM
- FRANJA_HORARIA
- REGION_NATURAL
- CATEGORIA_SEVERIDAD
- MORTALIDAD_MULTIPLE
- LESION_MULTIPLE

La variable objetivo CATEGORIA_SEVERIDAD se reconstruye con la misma lógica del proyecto:

- GRAVE_MORTALIDAD: cuando hay 2 o más fallecidos.
- GRAVE_LESIONADOS: cuando hay 3 o más lesionados y no aplica mortalidad múltiple.
- LEVE: los demás casos.

7. Prevención de fuga de información

Para no contaminar el modelado, se evitó usar variables que revelen directamente la severidad o el desenlace del siniestro.

No se usaron como predictoras:

- GRAVEDAD de la persona.
- LUGAR ATENCIÓN LESIONADO.
- LUGAR DE DEFUNCIÓN.
- Conteos directos de fallecidos o lesionados desde la base de personas.

Esto es importante porque el modelo debe aprender patrones asociados al riesgo, no recibir la respuesta indirectamente.

8. Validaciones implementadas

El notebook 02 ahora incluye validaciones básicas y de merges:

- Verifica que no se pierdan filas.
- Verifica que no se generen filas duplicadas.
- Verifica que CODIGO_SINIESTRO sea llave única.
- Verifica la consistencia de llaves antes de cruzar personas y vehículos.
- Verifica que la variable objetivo CATEGORIA_SEVERIDAD no cambie después de cada merge.
- Calcula cobertura de cada fuente.
- Calcula porcentaje de nulos de cada variable nueva.
- Verifica que los archivos de salida se exporten con utf-8-sig.
